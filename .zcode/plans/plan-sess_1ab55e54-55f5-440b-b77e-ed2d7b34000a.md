# carweb 迁移方案：Next.js 15 + PostgreSQL(Neon) + Vercel Blob + shadcn/ui

## 总体策略

在仓库新建 `web/` 目录搭建 Next.js 应用（App Router + React 19 + TypeScript + Tailwind v4 + shadcn/ui + motion）。旧 `client/`、`server/` 全程保持可运行，作为视觉与行为的对照；全部功能对等并验证后删除收尾。部署目标 Vercel（项目 Root Directory = `web/`）。

已确认的决策：数据库全新空库不搬测试数据；Postgres 用 Vercel Postgres/Neon；UI 用 shadcn/ui；图片走 Vercel Blob 公开随机 URL。

## 目标结构

```

```

## 阶段 0：脚手架与基建

1. `create-next-app` 初始化（TS、Tailwind v4、App Router、src 目录、ESLint）。
2. shadcn init + 添加组件：button、input、textarea、dialog、sheet、tabs、sonner(toast)、skeleton、badge、radio-group、label、separator。shadcn 主题变量（--background/--card/--border/--primary…）映射现有令牌值（--canvas/--surface-1/--hairline/--primary…），深浅双主题继续用 `prefers-color-scheme` 整组换值（沿用 global.css 现有做法）；搬运 material-bar、pressable、page-frame/scroll-area、card、sk 骨架、amount 等宽等全局类与两个无障碍兜底媒体查询；删除 Vant 变量桥接段。
3. Prisma schema 移植为 postgresql provider（字段、@@map/@map、金额 Int 分、级联关系全部不动），本地需 Postgres 连接串后跑 `migrate dev` 生成全新初始迁移。
4. `lib/prisma.ts`：PrismaClient 加 globalThis 缓存（防 dev 热重载多实例）。
5. `lib/auth.ts`：原样移植 scrypt 密码哈希（salt:hash 存 settings 表）+ HMAC-SHA256 无状态会话 Cookie（secret 存 settings 表，30 天）；**防爆破锁从进程内存 Map 改为 settings 表 KV**（`auth:fail:<ip>`，Serverless 多实例下生效）。`withAuth` 包装器 + AppError→`{message}` 统一错误处理替代 Express 全局中间件。
6. `lib/api-client.ts`：fetch 封装，语义与现 axios 封装一致（返回 data、401 跳 /login、错误 toast、skipToast 标记），32 个接口函数按域移植。
7. 手写移动组件 `mobile/`：BottomTabBar（含 tab 图标弹跳、safe-area）、PullToRefresh（touch 实现）、InfiniteScroll（IntersectionObserver）、ImagePreview（全屏 lightbox + 报价图保存条）、BottomSheet（Sheet 底部样式化 + 毛玻璃）、PlateKeyboard（从 Vue 移植）、数字滚动 hook（motion 的 animate，从呈现值续滚）。依赖：motion（React 版）、dayjs、lucide-react 图标。
8. 登录页 + auth 全套 API 先行，端到端验证鉴权链路（首次设密/登录/改密/防爆破）。

## 阶段 1：基础页面

- Home 工作台、Orders 列表（搜索 + 8 状态 tabs + 下拉刷新 + 无限滚动 + 骨架屏 + `?status=` 直达）、Customers 列表/详情、VehicleDetail、Reminders。
- 对应 API 路由移植：dashboard、customers、vehicles、orders 基础（列表/详情/状态流转）、reminders。
- 抽公共 statusMap/formatDate/formatAmount 到 lib（消除旧代码 4 处 statusMap 重复）。

## 阶段 2：核心流程（工作量最大）

- **Checkin 接车登记**（原 836 行最重页面）：客户/车辆选择与新建弹窗、车牌键盘、OCR（百度代理路由移植 + 前端 base64 编码直用）、9 张照片上传——**改为 Blob 客户端直传**：`/api/upload/token` 路由下发 token，前端 `@vercel/blob/client` 的 `upload()` 直传（绕开 Serverless 4.5MB 请求体限制），上传前沿用 compressImage 压缩；localStorage 草稿。
- **OrderDetail**：7 状态驱动的动作按钮组、收款弹窗（5 种方式）、编辑接车、报价长图预览保存（quoteCard.ts 纯 Canvas 生成，框架无关近乎原样移植）。
- **Quote 报价编辑器**：工时/配件条目 motion 增删动画、常用项目预设、小保养模板、复制上次项目、底部固定汇总栏、草稿。
- API 移植：报价保存/确认（事务重建明细）、维修记录、增项确认（重算 finalAmount）、质检（通过自动建结算单、pending 增项拦截）、结算单创建、收款/补款（事务重算 + 结清关催收）、交车（自动建回访 3 天/保养 3 月/欠款 7、30 天催收提醒）。
- 移植 settlement 回归脚本针对新服务层跑通（增项/挂账补款/零元结算场景）。

## 阶段 3：辅助与体验

- Stats 统计页（CSS 柱状图 scaleY 生长、数字滚动 hook）。
- 设置：改密码、店名（localStorage）、退出登录。
- PWA：`@serwist/next` 替代 vite-plugin-pwa（manifest、离线缓存、autoUpdate）+ InstallGuide 引导卡移植。
- 路由过渡：template.tsx 入场动画（tab 平级 fade 0.12s、详情页 push 右滑入），尊重 prefers-reduced-motion；App Router 不做退场动画（见已知差异）。

## 阶段 4：部署与收尾

1. 部署：`web/` 下 `vercel link`；创建 Neon Postgres 实例；配置环境变量 `DATABASE_URL`、`BLOB_READ_WRITE_TOKEN`、`BAIDU_OCR_API_KEY/SECRET`（可选）；`vercel env pull` 供本地开发；package.json 加 `postinstall: prisma generate`；首次 `prisma migrate deploy`。
2. 全流程验证清单：接车→报价→确认→维修→增项→质检→结算→收款/补款→交车→自动提醒；双主题切换；移动端真机与 PWA 安装。
3. 收尾：删除 `client/`、`server/`；更新根 package.json（dev/build/start 指向 web）、AGENTS.md（技术栈、目录结构、命令、UI 规范中 Vant 表述改为 shadcn）、README、DESIGN.md、.gitignore。
4. 全程在 `nextjs-migration` 分支按阶段 Conventional Commits 提交，验证通过后并回 master。

## 行为对等清单（不改语义）

金额一律整数分、单号规则（WO/SET+日期+3位序号）、状态机 allowedTransitions（pending_settlement/completed 仅走专用接口）、结算金额计算与超额收款拦截、交车自动提醒规则、所有中文注释与提交规范。

## 已知差异（有意为之）

- 图片 URL 从 `/uploads/xxx` 变为 Blob 全量 URL（`checkin_photos.file_path` 存完整地址），公开可访问但路径随机不可猜测。
- 防爆破锁改数据库 KV；会话/密码机制不变。
- 路由退场动画省略（App Router 限制），仅保留入场动画。
- stats 的 N+1 内存聚合保持原样，对等优先，后续可优化。
