# 部署到腾讯云轻量应用服务器

本方案面向 Ubuntu 24.04、Docker 29、4 核 4GB 的单机环境。应用与 CI 统一使用 **Node 24 + PostgreSQL 18**，保留原来的 CloudBase/MySQL Dockerfile 供旧部署方式使用。

原有 CI 已使用 Node 24，轻量服务器镜像沿用相同版本。Node 由容器镜像提供，服务器宿主机无需单独安装；本地终端的 Node 版本和 `@types/node` 类型包版本都不会决定容器内的运行版本。

当前准备使用的域名为 `runchenqixiu.top`，服务器位于上海。用户确认服务器为空、没有正式业务数据需要迁移，域名尚未备案。因此首次发布保持 `PUBLIC_ENABLED=0`，通过 SSH 隧道内测；备案完成后再开放域名 HTTPS。境内服务器域名备案要求见[腾讯云文档](https://cloud.tencent.com/document/product/1207/60423)。

## 发布链路

```text
推送默认分支 / 手动运行 CI
  → Lint、生产构建、结算回归
  → 构建 PostgreSQL 生产镜像
  → 打包应用 + PostgreSQL + Caddy 镜像
  → SSH 上传并校验发布包
  → 备份 → 数据库迁移 → 替换应用 → 数据库与页面探活
  → 已初始化且 PUBLIC_ENABLED=1 时启动 HTTPS 入口
```

PR 只检查，不部署。只有默认分支且仓库变量 `LIGHTHOUSE_DEPLOY_ENABLED=true` 时才自动发布。发布任务串行执行，并跳过已落后于默认分支的提交。服务器无需拉取 GitHub 源码或访问境外镜像仓库；构建好的镜像通过 SSH 传入。

## 目录与持久化

```text
/opt/carweb/
├── .env                 # 仅保存在服务器，权限 600
├── releases/<完整SHA>/  # 版本配置与脚本
├── current              # 当前成功发布版本的软链接
├── previous             # 上一成功版本
└── backups/             # 数据库与照片备份，保留最近 14 组
```

Docker Compose 项目名固定为 `carweb`。数据库、照片、证书分别保存在独立命名卷中，更新容器不会清空它们。数据库不映射宿主机端口，应用只映射 `127.0.0.1:3000`；公网入口由 Caddy 监听 80/443。服务设置内存上限及日志轮转，避免挤满 4GB 内存和 40GB 磁盘。

不要在正式环境执行 `docker compose down --volumes`，这会删除业务数据卷。日常发布由脚本更新应用。

## 1. 初始化服务器

先将本次部署配置推送到仓库。登录腾讯云服务器控制台，使用具备 Docker 权限的 SSH 账号执行：

```bash
docker version
docker compose version
whoami

# 首次只用仓库中的脚本生成运行配置，应用实际使用 CI 构建的镜像
git clone https://github.com/lipeh1/carfix_web.git carweb-init
sudo install -d -m 750 -o "$(id -un)" -g "$(id -gn)" /opt/carweb
bash carweb-init/deploy/lighthouse/init.sh /opt/carweb
nano /opt/carweb/.env
```

`init.sh` 生成随机数据库密码，不输出密码，也不会覆盖已有 `.env`。数据库密码保持脚本生成的十六进制格式；初始化数据库后修改 `.env` 中的密码不会自动修改库内密码。

确认这些配置：

```dotenv
DOMAIN=runchenqixiu.top
PUBLIC_ENABLED=0
STORAGE_DRIVER=local
```

OCR 密钥填入服务器 `.env` 的 `OCR_AGENT_API_KEY`。照片默认落持久化卷，不需要额外购买 COS；如果以后切换 COS，补齐同文件的 `COS_*` 变量，并另行迁移已有照片。

## 2. 配置 GitHub 发布凭据

为 CI 准备一对专用 SSH 密钥，将公钥加入该服务器登录账号的 `~/.ssh/authorized_keys`。该账号需要能直接运行 Docker，并能写入 `/opt/carweb`。私钥保存在 GitHub Secrets，不写入仓库或 `.env`。

在 GitHub 仓库 **Settings → Secrets and variables → Actions** 设置：

| 类型 | 名称 | 值 |
|---|---|---|
| Variable | `LIGHTHOUSE_HOST` | 服务器公网 IP |
| Variable | `LIGHTHOUSE_USER` | 上一步 `whoami` 返回的 SSH 用户名 |
| Variable | `LIGHTHOUSE_PORT` | SSH 端口，默认 `22` |
| Variable | `LIGHTHOUSE_DEPLOY_ENABLED` | 初始化完成后设为 `true` |
| Secret | `LIGHTHOUSE_SSH_KEY` | 专用 SSH 私钥完整内容 |
| Secret | `LIGHTHOUSE_KNOWN_HOSTS` | 经服务器控制台确认的 SSH 主机公钥记录 |

默认 SSH 端口为 22 时，可在服务器控制台生成主机公钥记录：

```bash
# 将 YOUR_SERVER_IP 替换为控制台显示的公网 IP；这里读取的是公钥
awk '{print "YOUR_SERVER_IP " $1 " " $2}' /etc/ssh/ssh_host_ed25519_key.pub
```

非 22 端口时，记录开头改为 `[YOUR_SERVER_IP]:端口`。工作流启用严格主机校验，不会临时信任扫描得到的未知主机公钥。

仓库使用 `production` Environment；若该环境配置了审批规则，发布会遵循已有规则。这里只需允许所选 SSH 账号连接，数据库端口不用开放。

## 3. 首次发布与内测

打开仓库 **Actions → CI → Run workflow**，选择默认分支。检查通过后会发布到 `/opt/carweb/releases/<SHA>`。首次成功日志会提示公网入口尚未开启。

在自己的电脑上建立 SSH 隧道，将用户和 IP 换成实际配置：

```bash
ssh -N -L 3001:127.0.0.1:3000 YOUR_SSH_USER@YOUR_SERVER_IP
```

浏览器打开 `http://localhost:3001`，设置系统访问密码并保存恢复码，然后内测接车、报价、收款、交车和照片上传。即使轻量服务器防火墙没有开放 3000 端口，该隧道也可访问本机绑定的应用。

只要保持 `PUBLIC_ENABLED=0`，后续更新仍可通过该隧道内测，不会开放 80/443 的应用入口。

## 4. 备案后开启域名与 HTTPS

1. 完成域名备案及腾讯云接入，填写服务器 `.env` 的 `ICP_BEIAN`。
2. 为 `runchenqixiu.top` 添加指向服务器公网 IP 的 A 记录。若没有配置可用 IPv6，不要保留错误的 AAAA 记录。
3. 在轻量服务器防火墙放行 TCP 80、443；UDP 443 仅用于可选的 HTTP/3。
4. 确认已通过 SSH 隧道设置系统访问密码，将 `.env` 中 `PUBLIC_ENABLED` 改为 `1`。
5. 执行 `bash /opt/carweb/current/deploy.sh /opt/carweb`。

脚本确认系统已初始化后才启动公网代理，并验证 HTTPS 证书和数据库状态。Caddy 自动申请及续签证书，详见[官方说明](https://caddyserver.com/docs/automatic-https)。首次签发需要正确的域名解析和可达的 80/443 端口。

## 5. 日常发布、备份与回滚

启用自动发布后，推送默认分支即可触发完整流程。应用更新会有短暂停机，本方案不承诺零停机。服务器 `.env` 改动后需要重新执行当前版本的 `deploy.sh` 才能应用。

查看状态与日志：

```bash
cd /opt/carweb
export APP_IMAGE="carweb:$(basename "$(readlink -f current)")"
docker compose -p carweb --env-file .env -f current/compose.yaml --profile public ps
docker compose -p carweb --env-file .env -f current/compose.yaml logs --tail 100 app db
docker compose -p carweb --env-file .env -f current/compose.yaml --profile public logs --tail 100 proxy
```

每次切换到新版本前自动备份。日常也可手动执行：

```bash
bash /opt/carweb/current/backup.sh /opt/carweb
```

每组包含 PostgreSQL 自定义格式备份、照片压缩包和 `.complete` 标记。备份时避免同时删除照片；COS 照片不包含在本地照片包里。备份保存在同一台服务器，正式使用后应复制到异地存储。脚本保留最近 14 组完整备份，不会删除数据卷。

应用未通过探活时自动恢复上一版应用镜像。**数据库迁移不会自动反向执行**，新迁移应兼容上一版应用；破坏性迁移需另行安排维护和数据恢复。

手动回滚应用（先确认上一版兼容当前数据库）：

```bash
cd /opt/carweb
previous_dir="$(readlink -f previous)"
export APP_IMAGE="carweb:$(basename "$previous_dir")"
docker compose -p carweb --env-file .env -f "$previous_dir/compose.yaml" up -d --no-deps --wait app
ln -sfn "$previous_dir" current
```

此操作不恢复或清空数据库。需要恢复数据时，先停止应用写入，再使用 PostgreSQL `pg_restore` 和对应照片包恢复，不能把应用回滚等同于数据回滚。

CloudBase 的旧说明仍在 `docs/部署-腾讯云CloudBase.md`。轻量服务器应使用 `Dockerfile.lighthouse`，不能用生成 MySQL Client 的旧 Dockerfile 连接 PostgreSQL。
